# Структурированные результаты

Полный JSON предназначен для сохранения свидетельств, интеграций или явного запроса. Это не ответ читателю по умолчанию. Следуйте [схеме](evaluation-result.schema.json); не подменяйте недостающие знания значениями только ради соответствия схеме.

## Связи в записи

- `scenarios` задают предположения об аудитории и условиях получения материала. Версия использует `rendering_id` и `scenario_id`.
- Каждая строка затрат указывает один сценарий, одну версию и одну базу измерения затрат. Используйте null в ссылке на версию, если ни одну версию нельзя обосновать; стоимость MAR и экономию тогда не сообщают.
- У каждой метрики затрат есть `status`, `value` и `reason`. `reported` требует измеренного числа. `withheld` и `not_applicable` требуют null, а не предположительного нуля.
- Наблюдения связаны с записями смысла, сценариями и версиями. Сохраняйте видимость исключённых и спорных наблюдений и их обоснований. Существенные неразрешённые споры блокируют P1, хотя спорные затраты и исключаются из консервативной экономии.
- `crac_allocations` указывают наблюдение, наблюдаемые границы оценки и полуоткрытый интервал `[start, end)` в заявленных единицах затрат. Длина интервала равна наблюдаемым единицам; вычтите единицы замены. В пределах одной строки затрат используйте каждый интервал один раз. Обеспечьте проверяемое соответствие единиц содержанию в описаниях границ и местоположения.
- `qualification` описывает только точное окончательное содержание в записи и названные сценарии. Это поле не фиксирует постоянную декларацию издателя. Содержание может соответствовать требованиям закреплённой версии, даже если использование последней версии остаётся непроверенным.
- `qualification.local_context_repair_needed` равно `true`, когда требуется восполнение контекста, `false`, когда для оцениваемого контекста оно не требуется, и `null`, когда это невозможно определить. Объясняйте неизвестное в `qualification.reason`; не используйте false в значении «не оценивалось». Только false может поддерживать `meets_requirements`.
- `latest_standard` фиксирует фактическую проверку или её отсутствие. Не используйте одну лишь установленную копию или тестовый пример, чтобы делать заявление о текущем последнем стабильном выпуске.

При недоступности всего содержания корректны пустые реестры смысла, версий и наблюдений и несообщённые измерения. Отдельная проверка заголовка не является полной оценкой статьи. В записях о канале раскрываются выборка и ограничения доступа; числа никогда не устанавливают фактический охват аудитории.

## Валидация

Выполните:

```text
node scripts/validate_result.js path/to/result.json
```

Необязательному помощнику валидации нужны Node и Python с пакетом `jsonschema`. Укажите исполняемый файл Python в `INFO_MINIMALISM_PYTHON`, если это не `python`; обычный путь поиска модулей, включая `PYTHONPATH`, учитывается. Отсутствующие зависимости дают код завершения 2, а не успешную валидацию. Для оценки и подсчёта текста Python не нужен.

Помощник применяет полную схему Draft 2020-12 с проверкой форматов, затем проверяет ссылки, отсутствие перекрытий, арифметику и несколько препятствий для соответствия требованиям. Код завершения 0 означает, что эти проверки пройдены; код 1 — ошибку схемы или связей. Это не доказывает сохранение содержания, добросовестность выборки, подлинность метаданных выпуска или постоянное соблюдение требований издателем. Проверяйте эти вопросы по существу.
